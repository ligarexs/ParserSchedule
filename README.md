# Парсер расписания → Google Sheets

Скачивает файл расписания с сайта ESIL University, разбирает пары группы
Б-ИТЗД 24/1 Р и перерисовывает блок в гугл-таблице.

## Файлы

| Файл | За что отвечает |
|---|---|
| `config.py` | Всё настраиваемое: группа, короткие названия предметов, цвета, id таблицы |
| `fetcher.py` | Скачивание файла с сайта, отслеживание обновлений по sha256 |
| `parser.py` | xlsx → список пар (`Lesson`) |
| `week_cache.py` | Склейка частичных файлов и ручных дней в полную неделю |
| `renderer.py` | Пары → сетка таблицы (значения, объединения, цвета) |
| `sheets_writer.py` | Запись сетки в Google Sheets одним batch-запросом |
| `main.py` | Пайплайн целиком |
| `preview.py` | Просмотр будущей таблицы в консоли, без сети |

## Установка

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

## Доступ к Google Sheets (один раз)

1. https://console.cloud.google.com → создать проект.
2. APIs & Services → Library → включить **Google Sheets API**.
3. APIs & Services → Credentials → Create credentials → **Service account**.
   Роль можно не выдавать, она здесь ни на что не влияет.
4. Открыть созданный аккаунт → Keys → Add key → JSON. Файл сохранить
   рядом с проектом как `service_account.json`.
5. Скопировать из JSON поле `client_email` (вида `...@...iam.gserviceaccount.com`).
6. Открыть вашу таблицу → Настройки доступа → добавить этот email как
   **Редактора**. Без этого шага будет ошибка 403 — сервисный аккаунт
   это отдельный «пользователь», он не видит таблицу автоматически.
7. В `config.py` вписать `SPREADSHEET_ID` — это кусок ссылки между
   `/d/` и `/edit`.

## Запуск

```bat
python main.py                 :: обычный прогон
python main.py --force         :: перезаписать, даже если файл не менялся
python main.py --dry-run       :: показать результат, не трогая таблицу
python main.py --file path.xlsx :: разобрать локальный файл
python preview.py path.xlsx    :: посмотреть вёрстку в консоли
```

Первый прогон стоит делать с `--dry-run`, второй — на копии таблицы.

## Автозапуск (Task Scheduler)

Создать `run.bat` рядом с проектом:

```bat
@echo off
cd /d "%~dp0"
call .venv\Scripts\activate
python main.py
```

Task Scheduler → Create Task → Triggers: Daily, повтор каждые 2 часа →
Actions: запуск `run.bat` → Settings: поставить «Run task as soon as
possible after a scheduled start is missed» (иначе прогоны при
выключенном ПК просто теряются).

Результат каждого прогона пишется в `run.log`.

## Неполные файлы недели

Университет публикует файлы не на всю неделю: разобранный образец
покрывал только среду, четверг и пятницу. Поэтому:

- парсер записывает только те дни, которые реально есть в файле;
- остальные дни берутся из `week_cache.json` (прошлая успешная выгрузка);
- дни, перечисленные в `config.MANUAL_DAYS`, парсер не трогает никогда —
  их можно вести руками в `manual_week.json` (формат см. в самом файле
  после первого прогона или в кэше).

## Что настраивать по ходу семестра

- **Новый предмет** → добавить строку в `SUBJECT_SHORT_NAMES`. Если этого
  не сделать, в таблицу попадёт полное название из файла и сломает
  вёрстку — такие случаи видно в `run.log`.
- **Спорная аудитория** (университет пишет все аудитории потока одной
  строкой) → `SUBJECT_OVERRIDES`, там же лежит текст сноски.
- **Номер недели** → `WEEK_LABEL`.
